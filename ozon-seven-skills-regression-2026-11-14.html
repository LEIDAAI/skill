发现的问题（待修）

  • 问题1 · A2 猫砂盆卡死：模型多路检索（字典→俄文 лоток / кошачий туалет→中文 skuNameZh）后，卡在中文名字段 skuNameZh 检索无法收敛，约15分钟未出结果，需手动停止。中文名索引对 OZON 商品检索不可靠，技能应提示中文名检索易空/易卡，优先俄文品类词。
  • 问题2 · 利润测算纯文字追问卡 turn：第一次「1990₽ 缺商品」时模型用纯文字追问（非 ask_user），导致 done 卡 false、发送按钮不恢复。第二次改用 ask_user 表单正常。技能应统一「缺必要信息时用 ask_user 追问」，避免纯文字追问卡住流。

纪律验证亮点（本轮复现）

  • 排序字段异常自动绕过：dailySales / 按月销量在部分组合异常返回0，模型在选品搜索 A、选品报告 A 等多个对话自动执行「去 sort 对照」绕过，识别为排序异常而非无数据。
  • 跨境逐 SKU 补验：SPU 不支持 storeType，模型一律对代表 SKU 用 storeType=1 补验，无法核验不计达标。
  • mallsNum / 店铺数失真不引用：类目趋势 C 明确「动销店铺字段口径漂移，不引用绝对值」。
  • 0 条不造表不造档位：选品搜索 C、选品报告 C 均如实报 0 + 补验路径，不虚构行、不造机会档位。
  • 实重/体积重区分：商品解析 C 用 max(实重,体积重) 取计费重，不把体积当计费重量。
