### 追问方式（ask_user 表单，缺1项问1题）
一次性收齐所有缺的必填项，不要挤牙膏；已答不重问。ask_user 必须单独调用（不与 view_skill/业务工具并发），每题显式写 id（同次调用唯一）、2–3 个 options 且每项含 label+description，需要自由输入设 allow_other=true（写在 question 对象内）。选项给可直接点的具体候选（如站点：美国站/德国站/日本站；类目：真实子类名2-3个+其他）。用户说"你看着办"时取最保守口径并在报告口径段声明假设；收到回答直接继续任务，不复述不二次确认。

### 报告收尾必带"下一步引导"
结论区后给 2–3 条可直接复制的下一步（如「要不要把差评拉出来看改进点？（场景19）」「要不要图搜1688拿货价？（场景14）」），只给可点文字建议，不开 ask_user。

### 报告固定结构（自上而下）
1. **页头**：场景名 + 站点 + 查询日 + 证据口径标签（例："采样2页 · 去重后14款 · 详情已核9款"）。
2. **KPI 卡行**：3~5 张卡，每卡 = 大数字 + 指标名 + 口径小字。
3. **明细表**：按本场景规定排序。商品行首列「主图+ASIN 同格」；关键词、类目、供应商、广告搜索词等非商品行使用对应对象名作首列，不虚构 ASIN、主图或商品链接。其后只列本场景所需字段。
4. **结论/建议区**：分档结论、可选方向、风险与红线；每条结论后标注依据字段。
5. **数据缺口与口径声明**：缺字段、降级口径、异常值、样本非全量，逐条列明。
6. **溯源**：本轮接口任务查看链接（<a target="_blank">），便于核对原始返回。

## 原始场景口径（业务目标与阈值依据）

在Amazon美站[大类]下筛选适合中小卖家（售价$20-60）的细分类目：

3. 三列补充指标（接口不直接提供，逐类目拉category_products Top100聚合）：均评分（按月销加权）/TOP10品牌份额（前10品牌销量÷总销量）/近半年新品份额（上架≥6个月商品销量÷总销量）
4. 两轮剔除：第一轮价位（<$20或>$60带外）与体量（月销过小）；第二轮品牌垄断（TOP10品牌>65%剔除）与新品空间（新品份额<3%剔除）
5. 推荐3个：垄断度低+新品通道存在+价位匹配+1688供给侧成熟四条同时满足，每个附数据依据
数据源：卖家精灵 category_tree/category_report/category_products

## ★ 深度交付层（对照运营报告骨架，优先于简化输出）
运营实测报告（宠物8子类7列全数据版）已验证本场景的完整交付形态：

1. **全指标表**：每个子类目7列全数据=在售商品数｜Top100月销｜均价｜加权评分（按月销加权）｜TOP10品牌份额（自聚合+官方双口径并列）｜近半年新品份额；全类目都算，不只算入围的。
2. **两轮剔除叙述**：第一轮=价位/体量/认证成本（逐类一句剔除理由）；第二轮=品牌垄断/新品无空间（如"咬胶TOP10品牌72%+新品份额0.5%全场最锁死"）；异常值核验留痕（如"新品份额43.1%经Top100逐条核验系白牌电子品集中放量"）。
3. **最终推荐**：🥇🥈🥉逐个=类目名+月销+均价+垄断度+新品份额+评分带+"为什么是它"一段；推荐必须垄断洼地+新品通道实证+价位匹配三证齐全。
4. **深挖结论**：首选类目的新品通道实证（如"FoxKnow双结棉绳74天月销833件+近半年新品5款进TOP100"）+基线对比（自聚合48.7% vs 上轮49.0%）。
5. **大类独立报告纪律照旧**：每个大类一份独立报告，不混类目。
