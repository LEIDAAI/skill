# youweiAI-amazon·选品报告

用户要求选品报告、是否进入某类目、商品候选决策时触发。这是终点技能：先明确站点、产品定义、硬条件、报告范围和采集日，建立证据底表（接口/参数/检索页码/ASIN与parent_asin/窗口/币种/已核字段/剔除原因）。若本轮已有可追溯工具结果，优先复用，不重复调用；跨历史对话的数据须写明历史日期，不能冒充本轮实时值。

按需串联：1. 类目词先确认精确节点，取Top100报告与两个以上完整月份趋势；对同一维度的Top3、Top5、Top10、Top20份额做非递减校验：一旦出现Top5<Top3等矛盾，整组该维度份额（包括单列Top3字段）全部弃用，正文、摘要、表格和风险结论都不可再引用该维度数值或依赖它推断“垄断”“进入难度”；品牌/卖家等其他维度仅在自身自洽且与原始字段吻合时可单列，不能拿其他维度反证已失效商品维度。卖家Top100销量份额的余数只能称该Top100样本内其余卖家的份额，不可称第三方新品可分流量、长尾可进入空间或未来销量；品牌或评论分层份额也不能直接推出新链接转化能力。未完月不参与比较；2. 关键词或类目搜索取得候选，注明实际页数、每页实得记录数，硬条件用详情核验，严格上架窗以listing_date，按parent_asin归组只称样本系列；3. 对少数代表ASIN查详情、评论原文/话题、卖家信息和平台估算费用，评论痛点的原文与话题计数分开；4. 已有采购、运费、币种和计费规则时才作情景利润，缺失则明确列出，不把接口平台毛利叫真实净利。需要更多数据时只补相应环节；无工具返回不得填历史示例。

报告结构：执行摘要（结论等级与证据限定）→查询条件与证据范围→类目体检及完整月趋势→候选表（ASIN、代表子体/父体、主图、标题商品链接、价格、估计月销、来源页码、硬条件核验）→代表款竞争与评论→平台费用/成本缺口→风险、待核字段与下一步。数据互相冲突时明确标记并撤回依赖该数据的判断；listing_date与在架天数/搜索日期矛盾时不得择一称严格上架日，列为待核并避免计算在架时间。商品表默认按核心指标降序；主图悬停在可交互网页中提供320×320白底圆角放大卡并跟随鼠标且边缘翻转，纯文本对话无此交互时仅给原图链接，不声称已实现；seller_id实得才给店铺链接。每个结论能追溯到本轮数据，未查模块标“未查证”，零结果不编机会档位；不从Top100或少量样本推全市场规模、增长或低竞争。对外只用youweiAI-amazon。

## 数值一致性与风险表述
平台佣金 platform_fee 只能用接口实值及其与售价之比描述；没有已核实的类目费率表，不以“≈15%”或其他假定费率打勾证明佣金准确。coupon=0 不能称券后优惠。估计月销×现售价要先与估计销售额算术核对，仅表示内部一致性。报告聚合窗口与榜单快照不一致时，两者分别列示，不互相替代；Top100分层款数合计不等于100时不得使用85款等款数或依赖它推冷启动门槛。Top5和Top10/20即便相等、非递减，也要与明细逐项复算；不一致即弃用。新链接进入难度、未来两月预测及“垄断”只保留为已查Top100范围的描述或待验证假设，不作全类目定论。

候选/入选商品表的主图列为强制项：必须用本次接口实得的图片URL渲染，不得因列多或条数多省略；加载失败留缺并标注，不用占位图。HTML报告中主图配悬停放大浮层：320×320、白底圆角阴影，mouseenter/mousemove跟随指针，靠近右/下边缘自动翻转，mouseleave隐藏。

## 输出形态（强制：HTML 报告 → 右侧预览面板）

结构：页头（报告名+站点+查询日+证据口径）→ KPI 卡行（3~5 张）→ 本场景明细表 → 结论与证据 → 风险和待核字段 → 溯源。商品行用主图+ASIN 同格；关键词、类目、供应商、广告词等非商品行只用本场景的对象字段，不虚构 ASIN/图片。排序遵守本场景要求。
