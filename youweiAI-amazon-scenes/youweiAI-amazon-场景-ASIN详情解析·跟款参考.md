### 报告收尾必带"下一步引导"
结论区后给 2–3 条可直接复制的下一步（如「要不要把差评拉出来看改进点？（场景19）」「要不要图搜1688拿货价？（场景14）」），只给可点文字建议，不开 ask_user。

4. **结论/建议区**：分档结论、可选方向、风险与红线；每条结论后标注依据字段。
5. **数据缺口与口径声明**：缺字段、降级口径、异常值、样本非全量，逐条列明。
6. **溯源**：本轮接口任务查看链接（<a target="_blank">），便于核对原始返回。

## 执行步骤
1. 确认ASIN列表与站点；逐条解析：五点卖点逐条、技术参数表格化、变体树（颜色/尺寸×价格）。
2. 变体家族结构写明子体数量与代表款，不把代表SKU销量当父体总销量。
3. 跟款评估：卖点同质化程度、参数门槛、变体覆盖缺口、价格带空隙。
4. 输出：解析表+跟款机会点+风险；缺失字段单列。

## 公共纪律与异常（详版见 youweiai-amazon-report-gen，不可豁免）
- 空值不补零，缺失标"未取得"；真实0与缺失分开；总命中≠样本，样本不推全市场并披露覆盖率。
- 表格每个数字溯源到本轮接口返回；严格0条不造表，放宽诊断单列标"诊断"。
- 502/504 如实记"环境异常"或走降级通道，不写成通过；execute_code 只1次机会，同参重复调用即熔断改人工核算；ask_user pending 时不得对该会话 API 续跑。

## ★ 深度交付层（对照运营报告骨架，优先于简化输出）
运营实测报告（BAGSMART B0F4283LS6解析版）已验证本场景的完整交付形态：

1. **单品KPI行**：售价（划线价+券）｜月销（$月销售额）｜BSR子类排名｜变体数（色×尺码结构）。
2. **Listing骨架节**：标题公式拆解（品牌+工艺词+品类词+场景词+品类补充的结构标注）+技术参数表+主图风格。
3. **变体结构表**：逐子体=变体名｜子ASIN｜月销；-1快照口径标注"不可相加称父体总销量"照旧。
4. **差评驱动节**：差评抽样数+差评率（如"300条抽样差评7条=2.3%"）+逐条星级/变体/原文；高频差评词提炼。
5. **跟款建议P0排序**：P0-1差评改进点（逐条=差评原文→跟款动作，如"came folded/distorted→定型纸板+挂装发货"）｜P0-2变体策略｜P0-3差异化机会；专利/商标提示不下结论照旧。


## ★★★ 全文复核补丁（2026-11-18审计：缺差评驱动节，最高优先级）
- **差评驱动节为必出层，不是可选**：详情解析流程内固定调用评论接口抽样（≥50条，实得多少写多少），逐条给星级/日期/变体/原话摘录+翻译；提炼差评高频词（词/提及数）；差评率=差评数÷抽样总数。

- 变体表逐子体补"子体价格/子体评论数"两列（接口返回即填；未返回标"—"并注明字段名）。
- 变体策略解读补"色彩宽度战略"：数一数色彩铺位数、指出疑似清库存色（近15天无销量更新的色）与上新建议（缩色保深度）。

3. 1688商品身份最少为：真实主图、接口返回的完整标题（title/subject等真实字段）、offerId。供应商名、店铺ID、SKU或“图搜结果”不能替代商品ID。Amazon与1688同款比对两端都独立展示各自身份，不把一端主图/标题/ID移给另一端。
