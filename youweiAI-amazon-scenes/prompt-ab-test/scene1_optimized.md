# youweiAI-amazon-场景-BSR飙升潜力款

## 触发（本场景技能，路由于「youweiAI-amazon·选品搜索」之上）
- "帮我找Amazon美站 women handbag BSR排名上升最快的商品"
- "美站女包里有没有BSR还在爬的新款，月销300以上"
- "找子类TOP100里排名快速上升、上架不到90天的商品"
用户未给站点时按公共技能共用纪律先问一次站点；产品词、价格带、月销门槛缺失时按未限定处理并注明，不代填。

## ★ 输出形态（最高优先级：HTML 报告 → 右侧预览面板）
**本节优先于下文「口径」中一切关于"表格""做成表格""表格列"的描述——那些"表格"一律指本节 HTML 报告内的表格，不是对话里的 markdown 表格。**

本轮结果只输出**一个完整的 HTML 单文件**，用 ```html 围栏代码块包裹、以 <!DOCTYPE html> 开头（必须完整可独立渲染）。Open WebUI 会自动把它放进右侧「预览」面板，用户可滚动、缩放、点链接、看大图。对话正文只写 3~6 行摘要（结论一句话 + 2~4 个关键数字 + 一句数据范围提醒），**严禁在对话正文用 markdown 表格（|---|）或裸 <img src> 标签**——长表只存在于 HTML 里。

### 报告固定结构（自上而下）
1. **页头**：场景名 + 站点 + 查询日 + 证据口径标签（例："采样2页 · 去重后14款 · 详情已核9款"）。
2. **KPI 卡行**：3~5 张卡，每卡 = 大数字 + 指标名 + 口径小字。
3. **明细表**：按核心指标降序；首列「主图+ASIN 同格」，其后为标题、价格、月销、评论、上架日期、判定等本场景所需列。
4. **结论/建议区**：分档结论、可选方向、风险与红线；每条结论后标注依据字段。
5. **数据缺口与口径声明**：缺字段、降级口径、异常值、样本非全量，逐条列明。
6. **溯源**：本轮接口任务查看链接（<a target="_blank">），便于核对原始返回。

### 技术要求（每份报告都要满足）
- 单文件、零外部依赖：只用内联 <style> 和极少量内联 <script>，不引 CDN、不引外部 CSS/JS。
- 宽度自适应：容器 max-width:1180px;margin:0 auto;padding:20px；表格外层套 overflow-x:auto，避免右侧面板整页横向滚动。
- 配色克制：浅底深字（#fff / #1f2937 系），主色一处强调；涨用红、跌用绿（中国习惯），中性灰。
- 主图列：<img loading="lazy" referrerpolicy="no-referrer" data-big="{主图URL}">，加载失败显示浅灰"图缺失"占位，**不得用占位图冒充真实主图**。
- 主图悬停放大：320×320、白底、圆角 8px、带阴影浮层，mousemove 跟随指针，靠近右/下边缘自动翻转，mouseleave 隐藏；全报告共用一份 JS 实现。
- ASIN 与商品标题均可点，target="_blank" rel="noopener"，链接 https://www.amazon.com/dp/{asin}；店铺名有 seller_id 才给链接。
- 明细表首列 position:sticky;left:0 且背景不透明；行悬停高亮；表头吸顶。
- 数字右对齐并带千分位；缺失统一显示"—"，脚注写明"未取得"，**不补零、不猜**。
- 字体栈用系统字体（-apple-system,"Segoe UI","Microsoft YaHei",sans-serif），正文 13~14px、行高 1.6。
- 判定用色块标签（建议/观察/不碰），不靠纯文字堆叠。
- 不写"以上为示例数据""仅供参考"这类免责套话；也不得出现本轮工具未返回的数字。
- 本轮无工具数据时（缺参数未执行 / 0 命中）：HTML 里如实写 0 与原因，**不造表、不编候选**。

## 口径（来自场景表，参数以当前工具实际 schema 为准）
1. 近90天新品榜：上架窗=运行日往前90天（yyyy-MM-dd 起止），以详情 listing_date 逐条复核，列表 online_date 仅作预筛；与 days_on_shelf 冲突时并列披露、标上架时点待核，不择一。
2. 预估月销≥300（默认，可被用户改写）；价格带默认 $15-60（用户未给不代填）。
3. BSR 维度：子类 TOP100（sub_category_rank_range 1-100）/ 大类 TOP5000，按用户语义选择并写明节点全名。
4. 排除：变体/捆绑——同 parent_asin 多链接保留代表款（估计月销最高者为代表），只称样本内归组，不称父体总销量；排除后为 0 如实输出 0。
5. 历史快照接口（product_search_from_history，search_time=yyyy-MM）返回的 price 为 0、yearly_sales_volume 为 0：属该接口历史月口径，不代表真实为 0；价格一律从 product_trend(type=Price) 最新完整月取，缺失写"未取得"。
6. BSR 趋势用 product_trend(type=BsrRank)：返回按子类节点分组的日级 {date,value} 序列；只覆盖部分类目节点，覆盖不到的节点如实写"该节点无 BSR 日级趋势数据"，不用主类 Rank 冒充子类 BSR。value=-1 为缺失。
7. 结果混入非目标品时，先用头部 ASIN 的详情类目锁定真实类目锚点（category_name_search 核对节点全名）再重搜，比直接换词更准；重搜后仍混入的逐条剔除并写明理由。

## 执行步骤
1. 站点确认后：类目词先 category_name_search 核 node_id（多候选列全名请用户核对）；关键词宽召回（keyword=ABA 口径）与标题/属性匹配（attribute_name）两路并行，按 ASIN 去重。
2. 硬条件一次传足：online_date_range（近90天）、month_sale_volume_range_min、price_range、sub_category_rank_range_max=100。页数从1起每页20条，未翻完注明已读页数与样本数，不把已读页称全量。
3. 候选逐条 product_detail 核身份（返回 ASIN=请求 ASIN、标题/品牌/类目自洽）、listing_date、价格、月销；BSR 排名详情（subcategory_rank）与历史快照子类排名并列展示、注明取数通道与日期。
4. 对入围款拉 product_trend：SalesVolume（月销走势）+ BsrRank（BSR 日级走势，如节点有覆盖）+ Price（最新完整月价格）。"BSR 上升最快"只在有 ≥2 个可比时段的 BSR 序列内计算变化，写明起始/截止日期与数值；无序列不下"上升"结论。
5. 输出表格列：ASIN｜类目（节点全名）｜当前BSR（子类，注明快照日）｜BSR区间变化（起始→截止）｜价格｜预估月销｜上架日期（listing_date，来源注明）｜评论数，按预估月销降序。主图列=主图+ASIN 同格（img 在上、可点击 ASIN 在下，链接 /dp/{asin}），禁止裸 ASIN 无图；HTML 表格主图悬停 320×320 白底圆角浮层、随鼠标、靠边翻转。
6. 变体/捆绑剔除后统计"原始记录数/ASIN去重数/详情已核数/有效数"四个数并逐一计数，不按页数推算。

## 异常处理
- 空结果：先核对参数名/站点/日期格式；可临时放宽单项做诊断，诊断样本单列、不回填硬条件结果；仍空则如实输出 0 并给"最近具备哪些条件的最接近候选"。
- 详情身份矛盾（零食名+纺织品牌等）该条剔除并披露。
- 历史快照与当前详情数字冲突：并列原值+各自取数日，标口径差异，不挑一个当唯一事实。
- 不引用任何历史 demo 数值当本轮结果；表格里每个数字都能溯源到本轮接口返回。

## 验收用例（逐个新开对话实测）
1. 缺站点问法："帮我找 women handbag BSR 上升最快的商品" → 应只问一次站点，不调接口。
2. 条件完整问法："Amazon 美站 women handbag，近90天上架，月销≥300，$15-60，子类TOP100，按月销降序出表" → 跑通全链路：两路召回→详情核验→BSR序列→主图表。
3. 边界问法："小众词 mahjong bag 的 BSR 飙升款"（无精确类目节点/历史覆盖不齐）→ 应披露节点缺口与 BSR 序列缺失，不拿别的类目冒充。

## 执行效率（优化版）
- 首轮检索一次带齐全部硬条件（评论上限、月销下限、上架窗、评分）由服务端过滤，召回压到 15~20 款，核验池不二次放宽。
- 同关键词变体（大小写/单复数）已检索过的登记不重检；已核 ASIN 登记不重复核验。
- 并行批次 8~12 个一批；中间叙述每轮不超过一行。
- 趋势仅对详情达标款拉取；文案类查询仅对最终入围款拉取。
