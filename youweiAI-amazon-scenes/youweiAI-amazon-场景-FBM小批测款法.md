# youweiAI-amazon-场景-FBM小批测款法

## ★ 必填项与追问（强制执行，优先于下文任何“缺参数就问一次”的表述）


### 必填项
站点；类目或产品词


### 可选/可默认项（缺了就按“未限定”处理，并在报告数据缺口里注明，不代填、不追问第二遍）
采购价区间、首批预算


### 追问方式（ask_user 表单，缺1项问1题）
一次性收齐所有缺的必填项，不要挤牙膏；已答不重问。ask_user 必须单独调用（不与 view_skill/业务工具并发），每题显式写 id（同次调用唯一）、2–3 个 options 且每项含 label+description，需要自由输入设 allow_other=true（写在 question 对象内）。选项给可直接点的具体候选（如站点：美国站/德国站/日本站；类目：真实子类名2-3个+其他）。用户说"你看着办"时取最保守口径并在报告口径段声明假设；收到回答直接继续任务，不复述不二次确认。

### 报告收尾必带"下一步引导"
结论区后给 2–3 条可直接复制的下一步（如「要不要把差评拉出来看改进点？（场景19）」「要不要图搜1688拿货价？（场景14）」），只给可点文字建议，不开 ask_user。

## 触发（本场景技能，执行时按需调用已绑定的公共技能与工具）
- 原始问法：帮我用FBM测款逻辑选品：订单数>2、按采购价分档选品
- 变体问法按语义匹配本场景；用户未给站点先问一次站点。


## ★ 输出形态（最高优先级：HTML 报告 → 右侧预览面板）
**本节优先于下文「口径」中一切关于"表格""做成表格""表格列"的描述——那些"表格"一律指本节 HTML 报告内的表格，不是对话里的 markdown 表格。**

有实得结果时输出**一个完整的 HTML 报告**，用 ```html 围栏代码块包裹、以 <!DOCTYPE html> 开头。Open WebUI 已验证可在右侧「预览」面板渲染。对话正文只写 3~6 行摘要，长表放在 HTML 里。缺少必要输入时直接提问；0 命中时说明原因，不能编造候选。场景21若用户明确需要 Excel 对账，HTML 用于预览，另交付可核对的明细文件。


### 报告固定结构（自上而下）
1. **页头**：场景名 + 站点 + 查询日 + 证据口径标签（例："采样2页 · 去重后14款 · 详情已核9款"）。
2. **KPI 卡行**：3~5 张卡，每卡 = 大数字 + 指标名 + 口径小字。
3. **明细表**：按本场景规定排序。商品行首列「主图+ASIN 同格」；关键词、类目、供应商、广告搜索词等非商品行使用对应对象名作首列，不虚构 ASIN、主图或商品链接。其后只列本场景所需字段。
4. **结论/建议区**：分档结论、可选方向、风险与红线；每条结论后标注依据字段。
5. **数据缺口与口径声明**：缺字段、降级口径、异常值、样本非全量，逐条列明。
6. **溯源**：本轮接口任务查看链接（<a target="_blank">），便于核对原始返回。


### 技术要求（每份报告都要满足，详版见 youweiai-amazon-report-gen）
- 单文件零依赖（内联 style，不引CDN）；容器 max-width:1180px 居中，表格外层 overflow-x:auto。
- 主图列 <img loading="lazy" referrerpolicy="no-referrer" data-big="{主图URL}">，加载失败显示"图缺失"占位，不用占位图冒充；悬停放大 320×320 白底圆角、mousemove 跟随、近右/下边缘翻转、mouseleave 隐藏，全报告共用一份JS。
- ASIN/标题可点新标签开 https://www.amazon.com/dp/{asin}；有 seller_id 才给店铺链接。
- 数字右对齐千分位；缺失显示"—"并脚注"未取得"，不补零不猜；涨红跌绿。
- 不写"示例数据/仅供参考"套话；无工具数据时如实写 0 与原因，不造表不编候选。

## 原始场景口径（业务目标与阈值依据）
下文是场景表原文，包含历史工具名、示例及旧执行建议；与本技能的「执行步骤」「公共纪律」冲突时以后两者为准。原文中的降档只用于另列诊断结果，不能放宽严格达标口径；没有真实字段时标为不可判定。
1. 口径：1688筛类目→订单数>2→按采购价分档（便宜的$100内多选、贵的少选）→看样品→采购10几个发海外仓测款
2. 件数口径：看总件数不看日件数（日件数有滞后）
3. 输出：商品｜订单数｜采购价档位｜建议测款数量｜样品清单
4. 测款成功标准：有持续出单→转批量采购；无单→下架换款
口径补充：订单>2；总件数（非日件数）；采购价分档
过滤补充：轻小件优先


## 数据源
- 1688选品库 product_search_list（订单数排序/过滤）
- ali_offer_sku_prices（拿货价分档）


## 执行步骤
1. 与用户确认类目词（未给则问一次）；1688选品库筛类目→订单数>2 过滤。
2. 看总件数不看日件数（日件数有滞后），逐款记录订单数与总件数。
3. 按采购价分档：低价档（如≤¥30）可多选款、高价档少选；轻小件优先，超大超重标注。
4. 输出：商品（主图+链接）｜订单数｜总件数｜采购价档位｜建议测款数量｜样品清单；按订单数降序。
5. 测款成功标准写明：有持续出单→转批量采购；无单→下架换款。1688 与亚马逊间的适配风险（认证/体积/季候）单列提示。

## 公共纪律与异常（详版见 youweiai-amazon-report-gen，不可豁免）
- 空值不补零，缺失标"未取得"；真实0与缺失分开；总命中≠样本，样本不推全市场并披露覆盖率。
- 表格每个数字溯源到本轮接口返回；严格0条不造表，放宽诊断单列标"诊断"。
- 502/504 如实记"环境异常"或走降级通道，不写成通过；execute_code 只1次机会，同参重复调用即熔断改人工核算；ask_user pending 时不得对该会话 API 续跑。

## 执行效率（详版见 youweiai-amazon-report-gen）
先快后准：已取数据不重跑；检索从第1页起每页20条并记录页码；详情只核验拟入表候选；出稿前逐项自检再交付。

## ★ 深度交付层（对照运营报告骨架，优先于简化输出）
运营实测报告（FBM小批测款三口径核验）已验证本场景的完整交付形态，本场景报告必须达到以下深度：

1. **样本量核验设计**：对每个口径给出"真实性判据"——同口径下热门类目同接口可返回整页20条时，本类目返回8款/13款即口径真实命中而非数据截断；判据与结论写入报告。
2. **三口径并列**：宽松口径、严格口径（如评论≤100+⭐≥4.5+上架≤6月+月销≥300+$15-60）分别出清单；方法论节写明"TOP N 逐款精查=深度优先于覆盖广度"的设计，非数据上限。
3. **逐款核验深度**：精查款每款独立调用14月趋势核实，历史季节形态作为测款参考判据；未核SKU与重量未核款单列"待核"，不冒充已核。
4. **测款数量分档**：输出逐款建议测款数量+首测货值合计；低价档多选/高价档少选的分档逻辑写明。
