### 缺图/缺文件的专用问法（仅场景14/15/21这类必须文件的技能）

- 场景14/21 缺 ASIN/售价/文件 → 同上，给出可点的补参路径，不得静默按默认值跑。

### 报告固定结构（自上而下）
1. **页头**：场景名 + 站点 + 查询日 + 证据口径标签（例："采样2页 · 去重后14款 · 详情已核9款"）。

3. **明细表**：按本场景规定排序。商品行首列「主图+ASIN 同格」；关键词、类目、供应商、广告搜索词等非商品行使用对应对象名作首列，不虚构 ASIN、主图或商品链接。其后只列本场景所需字段。
4. **结论/建议区**：分档结论、可选方向、风险与红线；每条结论后标注依据字段。
5. **数据缺口与口径声明**：缺字段、降级口径、异常值、样本非全量，逐条列明。
6. **溯源**：本轮接口任务查看链接（<a target="_blank">），便于核对原始返回。

## 原始场景口径（业务目标与阈值依据）
下文是场景表原文，包含历史工具名、示例及旧执行建议；与本技能的「执行步骤」「公共纪律」冲突时以后两者为准。原文中的降档只用于另列诊断结果，不能放宽严格达标口径；没有真实字段时标为不可判定。
分析Amazon SP广告搜索词报告（运营诊断场景，用户供文件模式🟡可跑）：
1. 数据入口：用户提供广告后台导出的搜索词报告CSV/XLSX（SellerSpace/广告API均未接入，不支持实时导出）；核验字段完整性（搜索词/匹配方式/展示/点击/花费/订单/销售额），缺失字段向用户说明
2. 指标计算纪律：CTR/CVR/ACoS/CPC/CPA/ROAS按原始数据重算——先累加基础数（点击/花费/订单/销售额）再算比例，禁止平均各行百分比；零分母留空不填0；混币种不相加（多币种分列输出）
3. 语义五分类（基于商品事实判断）：核心相关词/长尾属性词/泛词/ASIN词（竞品ASIN定位词，保留不替换）/明显不匹配词；语义判断资料不足时标"待核实"不硬分类
4. 来源裁决（本场景关键）：同词多匹配来源（精准/词组/广泛/自动）分别评估，禁止聚合后一刀切——典型裁决：精准来源有成交+自动来源无单→控费自动来源而非否定整个词；聚合ACoS会掩盖来源差异
5. 四档动作候选（默认阈值TargetAcos=0.35/StopClicks=10/StopSpend=10仅为筛选候选，非盈亏标准，用户可自定义）：
① 保留：语义精准+ACoS低于参考线
② 控费候选：有订单但超参考线→降竞价/控预算（不自动否定）
③ 观察：无订单且样本少（<StopClicks或<StopSpend）→标记观察，达阈值复核
④ 精准否定候选：无订单达阈值+语义不匹配→完整词精准否定（精准否定优先于词组/词根否定，扩大否定前检查受影响的相关长尾词，避免误伤）
6. 输出：聊天结论（核心发现+关键数字）→Excel明细（产品/活动/匹配方式/原始数据/语义分类/动作候选/理由）；原始明细与计算结果对账，花费/订单/销售额自洽校验，异常行解释skipped原因
7. 本场景只产建议：执行广告修改需用户在广告后台操作，agent不做写操作

## 执行步骤
1. 用户必须提供SP搜索词CSV/XLSX；缺文件时先索取。解析原始字段与日期、币种，缺展示/点击/花费/订单/销售额时标注无法计算的指标。
2. CTR、CVR、ACoS、CPC、CPA、ROAS先合计基础数再计算；零分母留空，多币种分别汇总。按核心相关/长尾属性/泛词/ASIN词/明显不匹配分类；语义资料不足标待核。
3. 同一搜索词按精准/词组/广泛/自动来源分别裁决。TargetAcos=0.35、StopClicks=10、StopSpend=10是默认候选阈值，非盈亏线；保留/控费/观察/精准否定候选逐来源给依据，避免整词误伤。
4. 聊天摘要与可预览HTML展示分类汇总及动作；用户要求Excel对账时另交可核的逐行明细，保留产品、活动、来源、原值、计算值与理由，并核对花费、订单、销售额的合计。只给建议，不操作广告后台。

## 公共纪律与异常（详版见 youweiai-amazon-report-gen，不可豁免）
- 空值不补零，缺失标"未取得"；真实0与缺失分开；总命中≠样本，样本不推全市场并披露覆盖率。
- 表格每个数字溯源到本轮接口返回；严格0条不造表，放宽诊断单列标"诊断"。
- 502/504 如实记"环境异常"或走降级通道，不写成通过；execute_code 只1次机会，同参重复调用即熔断改人工核算；ask_user pending 时不得对该会话 API 续跑。
