# youweiAI-amazon-场景-找评论少销量高的商品

## ★ 必填项与追问（强制执行，优先于下文任何“缺参数就问一次”的表述）

### 必填项
站点；类目或产品词

### 可选/可默认项（缺了就按“未限定”处理，并在报告数据缺口里注明，不代填、不追问第二遍）
评论上限、月销下限

### 追问方式（必须用 ask_user 表单，禁止纯文字发问后干等）
1. 一次性收齐所有缺的必填项，**不要一项一项挤牙膏**；缺 1 项就只问 1 题。
2. `ask_user` **必须单独调用**，不与 `view_skill` 或任何业务工具并发。
   - **每题必须显式写 `id`（非空字符串、同次调用内唯一）**，例如 `{"id":"target_product","question":"...","options":[...]}`；漏 `id` 会被接口直接报错 `Each question requires a non-empty id`，客户就看不到选项卡片。
   - `allow_other` 必须写在 **question 对象内**（不是顶层）。
3. 每题 **2–3 个 options**，每项必须含 `label` 和 `description`；需要自由输入（如自定义类目、其他子类）时设 `allow_other=true`。
4. 选项要**给客户可直接点的具体候选**，不要只写“是/否”。例：
   - 站点：`美国站`（市场规模最大，竞争最激烈）/ `德国站`（欧洲头部，需关注VAT）/ `日本站`（本土竞品少）
   - 类目：给出该站真实子类名 2-3 个 + `其他`（允许输入）
   - 图片/文件缺失：`我上传图片`（支持图片直链或附件）/ `我先贴商品链接，你来提图` / `跳过图片，只用链接`（若本场景必须图片则不提供此选项）
5. 用户已回答的项不再重复问；用户说“你看着办/按默认”时，取最保守口径并声明假设。
6. 收到回答后**直接继续原任务**，不要复述问题、不要重新确认。

### 缺图/缺文件的专用问法（仅场景14/15/21这类必须文件的技能）
- 场景15 缺图片 → 必须用 ask_user 提示：“本技能需要一张商品图才能反查 1688 货源”，给出 `上传图片` / `贴商品链接由我取图` / `先看这个技能怎么用`（说明+示例图格式）三个选项，**不得用文字猜商品、不得编造货源**。
- 场景14/21 缺 ASIN/售价/文件 → 同上，给出可点的补参路径，不得静默按默认值跑。

### 报告收尾必带“下一步引导”（不做 ask_user，只给可点的文字建议）
HTML 报告结论区之后，固定给 2–3 条**下一步可做**的引导，例如：
- 「要不要把这批款的差评拉出来看改进点？（场景19）」
- 「要不要按 $25/$30/$35 三档做毛利敏感性？」
- 「要不要换德国站看同样条件有没有机会？（场景10）」
只写建议文字，**不要在结尾强制再发 ask_user**，避免客户被反复弹窗卡住。
## 触发（本场景技能，执行时按需调用已绑定的公共技能与工具）
- 原始问法：我想看看[站点]的[产品词]里，有没有新卖家已经做起来的款。找出评论不到[200]条、月销超过[300]的商品（同款变体合并），做成表格→分析共同点→TOP款逐月趋势判断新起还是稳定→能不能跟+从哪切入
- 变体问法按语义匹配本场景；用户未给站点先问一次站点。

有实得结果时输出**一个完整的 HTML 报告**，用 ```html 围栏代码块包裹、以 <!DOCTYPE html> 开头。Open WebUI 已验证可在右侧「预览」面板渲染。对话正文只写 3~6 行摘要，长表放在 HTML 里。缺少必要输入时直接提问；0 命中时说明原因，不能编造候选。场景21若用户明确需要 Excel 对账，HTML 用于预览，另交付可核对的明细文件。

### 报告固定结构（自上而下）
1. **页头**：场景名 + 站点 + 查询日 + 证据口径标签（例："采样2页 · 去重后14款 · 详情已核9款"）。
2. **KPI 卡行**：3~5 张卡，每卡 = 大数字 + 指标名 + 口径小字。
3. **明细表**：按本场景规定排序。商品行首列「主图+ASIN 同格」；关键词、类目、供应商、广告搜索词等非商品行使用对应对象名作首列，不虚构 ASIN、主图或商品链接。其后只列本场景所需字段。
4. **结论/建议区**：分档结论、可选方向、风险与红线；每条结论后标注依据字段。
5. **数据缺口与口径声明**：缺字段、降级口径、异常值、样本非全量，逐条列明。
6. **溯源**：本轮接口任务查看链接（<a target="_blank">），便于核对原始返回。

### 技术要求（每份报告都要满足）
- 单文件、零外部依赖：只用内联 <style> 和极少量内联 <script>，不引 CDN、不引外部 CSS/JS。
- 宽度自适应：容器 max-width:1180px;margin:0 auto;padding:20px；表格外层套 overflow-x:auto，避免右侧面板整页横向滚动。
- 配色克制：浅底深字（#fff / #1f2937 系），主色一处强调；涨用红、跌用绿（中国习惯），中性灰。
- 仅商品行使用主图列：<img loading="lazy" referrerpolicy="no-referrer" data-big="{主图URL}">，加载失败显示浅灰"图缺失"占位，**不得用占位图冒充真实主图**。非商品行无需主图。
- 主图悬停放大：320×320、白底、圆角 8px、带阴影浮层，mousemove 跟随指针，靠近右/下边缘自动翻转，mouseleave 隐藏；全报告共用一份 JS 实现。
- 有真实 ASIN 的商品行：ASIN 与标题可点，target="_blank" rel="noopener"，链接使用查询站点对应的 Amazon 域名；店铺名有 seller_id 且链接可验证才给链接。非商品行不强制商品链接。
- 明细表首列 position:sticky;left:0 且背景不透明；行悬停高亮；表头吸顶。
- 数字右对齐并带千分位；缺失统一显示"—"，脚注写明"未取得"，**不补零、不猜**。
- 字体栈用系统字体（-apple-system,"Segoe UI","Microsoft YaHei",sans-serif），正文 13~14px、行高 1.6。
- 判定用色块标签（建议/观察/不碰），不靠纯文字堆叠。
- 不写"以上为示例数据""仅供参考"这类免责套话；也不得出现本轮工具未返回的数字。
- 缺必要参数时在对话中直接提问；执行后严格条件 0 命中时在报告中如实写 0 与原因。诊断性放宽结果独立标注，不回填严格命中，**不造表、不编候选**。

## 公共纪律（不可豁免）
- 用户未给站点时先问一次站点，不默认美国站、不调接口；产品词/价格带/门槛缺失按"未限定"处理并在结果注明，不代填。
- 空值不补零；缺字段单列"未取得/接口未返回"；发现时间(minCreateTime)不作上架时间(listing_date/online_date)，冲突并列披露。
- 总命中与实际取样分开写明（原始记录数/去重数/详情已核数/有效数）；样本不推全市场，不把已读页称全量。
- 结果混入非目标品时用头部 ASIN 详情锁定类目锚点（category_name_search）再重搜，仍混入的剔除并写明理由。
- 不引用历史 demo 数值；表格里每个数字都能溯源到本轮接口返回或明确标注的用户输入；严格条件 0 条不造表。可列实际取到的最接近候选及差距项，必须与达标结果分开。
- 输出三段式：KPI 摘要卡 + 明细表 + 结论/建议（统一落在 HTML 报告内）；排序遵守本场景原始要求，未指定时按核心指标降序。
- 商品表有实际主图与 ASIN 时同格展示；缺主图显示缺失而非伪造。非商品对象不要求 ASIN 与图片。商品图悬停 320×320 白底圆角浮层、随鼠标、靠边翻转防溢出。
- 涉及利润：5% 损耗作为单独成本情景，说明按售价或采购价计提的基数；不可与用户指定的毛利定义混淆。采购价/物流/佣金/汇率缺项单列，用户假设只作情景测算、不称真实净利。

## 执行效率（提速但不降质）
- **查询日唯一来源**：报告页头的查询日只能来自本轮 get_current_timestamp（或等价时间接口）的真实返回；接口未返回统计时点时如实写"快照未返回统计时点"，**严禁凭空编写日期**。
- **同阶段取数必须并行**：同一条工具调用可批量传入多个目标时一次传全量；不支持批量的，把同类型无依赖的调用合并进同一轮并行发出（例如逐款详情、逐款趋势、多类目报告、多词趋势，按 6~8 个一批并行），禁止一个一个串行轮询。并行批次的返回逐条对应核验，质量口径不变。
- **中间叙述最小化**：每轮调用之间的过程文字压缩到一行以内（只写"已取得X，继续Y"），不展开数字复述、不做阶段小结；所有分析性文字集中在最终报告里。表格中的数字溯源要求不因省略叙述而放松。
- **趋势不逐月拉**：需要月度序列时优先一次调用取全序列；只有当序列明显不完整（如当月进行中需补历史月）才补调用，并说明原因。
- **不做全量翻页除非必要**：快照类取数按场景规定的样本量（Top20/Top100/第1页）执行，超量翻页只在用户明确要求全量时进行，并声明样本边界。
- 报告生成直接在回复中输出完整 HTML；不要调用 execute_code 落盘文件再展示（曾有生成大文件挂起 40 分钟的案例）。涉及复杂合计时可用 execute_code 做纯计算（秒级），但输出仍走回复内 HTML。

## 异常处理
- 空结果：先核对参数名/站点/日期格式；可临时放宽单项做诊断，诊断样本单列、不回填硬条件结果；仍空如实输出 0。
- 接口字段缺失/异常值（如1970日期、-1排名）不当作真实值，标注异常并改用替代口径或标"待核"。
- 历史快照与当前详情冲突：并列原值+各自取数日，标口径差异，不择一当唯一事实。

## 验收（逐个新开对话实测）
- 缺关键参数问法 → 应先问一次（站点/类目/文件），不调接口、不默认补齐。
- 条件完整问法 → 跑通对应数据源全链路，输出 HTML 报告（KPI+明细表+结论），右侧预览可正常渲染。
- 边界问法 → 数据缺口如实披露，降级口径置顶，不拿别的数据冒充。
- 渲染问法 → 检查右侧预览：表格不破版、主图能显示、悬停放大可用、ASIN 能跳转。

## 执行效率（优化版）
- 首轮检索一次带齐用户明确给出的硬条件，至少3个有不同检索意义的产品/形态词分别采样Top20；记录每词返回和分页边界。不得人为把总候选池压到15~20款。先完整呈现去重采样池，再按实际硬条件逐款核验；不得用只展示Top11/Top15代替整个已取池。必要翻页用于补足召回覆盖，不放宽硬条件。
- 同关键词变体（大小写/单复数）已检索过的登记不重检；已核 ASIN 登记不重复核验。
- 并行批次 8~12 个一批；中间叙述每轮不超过一行。
- 趋势仅对详情达标款拉取；文案类查询仅对最终入围款拉取。

## ★ 深度交付层（对照运营报告骨架，优先于简化输出）
