两套专家已有七技能路由和数据纪律，值得做一次规则收敛。TEMU 优先处理异步交付、工具依赖和报告收口；OZON 优先处理补丁之间的矛盾、白名单和取样预算。这是配置质量判断，不是本轮对话成功率结论。

应优先优化的具体问题

优先修复 · T1 TEMU：iframe 指令互相冲突

系统与选品技能仍要求 processing 时直接输出 iframe；后文又明确禁止原生 iframe。冲突已在当前线上文本确认。

“返回 status=processing 时直接输出返回的 iframe 字段”
“只给 view_url 可点击链接（新标签打开），不输出原生 <iframe> 标签”

优化：统一为任务进行中只交付真实预览链接和状态；缺少链接就说明尚不可预览。删除旧分支。沙箱历史故障不算本轮重现。

位置：TEMU 专家 system、youweiai-tmeu-selection-search；历史沙箱说明复制到多技能。

优先修复 · T2 TEMU：异步任务状态与报告完成状态没有闭合

规则禁止轮询，又要求用全部真实样本计算统计。processing 只有任务与计数时，尚不能证明模型已读取明细，也不足以生成完整报告。

“不轮询 job_status/job_aggregate；done 后本轮检索立即结束”
“汇总必须基于本轮真实返回计算”

优化：区分“已提交 / 处理中 / 已可读取 / 已生成报告”，分别记录总命中、保存条数、已读取条数、语义过滤后唯一条数。明确允许如何读取同一任务，禁止重复启动同参任务；未取得明细就不宣称分析完成。

位置：TEMU 选品、竞品、报告技能。实际 processing 返回结构和自动续接能力待 UI 验证。

优先修复 · O1 OZON：类目趋势流程与工具白名单不一致

该技能定义商品取样和搜索预算，公共流程也指向 SPU 搜索，但其专用白名单只有字典、字段、大盘、品牌与 SPU 详情，未包含 SPU 搜索及 SKU 补验搜索。

“用户允许商品取样时再按已核验类目语义取样”
“工具白名单：yq_dict_lookup,yq_fields_lookup,yq_ozon_market_stat,yq_ozon_brand_search,yq_ozon_spu_detail”

优化：明确选择一种路径：由选品技能负责取样、趋势技能只消费结果；或按需补齐受控工具白名单。不能同时允许流程又禁止其必要工具。

位置：youweiai-ozon-category-trend。该矛盾已由当前正文确认，实际拒调或误调尚未重现。

优先修复 · O2 OZON：代码故障回退与最终交付门禁冲突

“最终HTML必须在最后一次成功execute_code的stdout完整输出”
“代码沙箱不可用……仍须输出完整HTML报告……只展示工具真实返回的原始字段值”

优化：设正常计算分支和计算失败分支：前者展示已验证统计，后者展示原始字段和待计算项并自然完成。回退分支明确豁免成功 stdout 要求，不能依赖同一失败环境才能收口。

位置：youweiai-ozon-category-trend。现有文本未明确两个分支的优先级。

流程优化 · T3 TEMU：追问改成按任务判断，避免全局拦截

现有全局要求先补托管和站点。对于公式计算、已有结果解读、多国价格解析，有时不需要单一目标站点；统一等待可能增加不必要往返。

优化：仅对实际查询或计费所必需的缺项追问，一次收集；条件齐全就直接运行。已明确的条件复用，用户仅要求列缺项时完成该轮。多站点 / 全部返回站点可作为合法口径。

这是规则优化建议，尚未观察到本轮真实对话中的过度追问。

流程优化 · T4 / O3 两平台：统一样本预算、展示数量和停止条件

TEMU 与 OZON 大样本规则强调“取够 N”，OZON 趋势则把 N 定义为累计返回的不同 SPU 上限；OZON 选品还有每次 size≤N 的表述。跨技能串联时含义不够统一。

优化：区分“最多检查 N 个候选”“目标输出 N 个合格品”“只展示 N 行”，不把三者当同一预算。明确不足 N、分页重复、语义不符、两轮无新增或费用上限的停止条件；汇总里的 N 必须取实际有效数，不能机械照抄用户目标。

涉及两平台选品、趋势、店铺、报告；需要跨技能回归，不能只修一个段落。

依赖核验 · T5 TEMU：利润找源与当前显式绑定存在依赖缺口

利润技能写了供货侧图搜与 SKU 核价流程；专家显式仅绑定 TEMU 连接，系统又限定 TEMU 工具。仅凭配置不能保证新会话能执行找源。

优化：先核查运行时工具列表；供货依赖缺失时明确需要的成本信息并完成可计算部分。用户已给拿货价则直接复用，不为走流程额外找源。不要把本项静态风险写成“当前所有找源接口均不可用”。

维护优化 · T6 / O4 两平台：重复规则、历史故障与案例补丁需要收敛

TEMU 系统中“大样本展示 / 分页重复 / 语义过滤”三段各重复一遍；多技能复制相同沙箱历史说明。OZON 趋势、解析等技能堆叠多轮修补，仍含具体日期、829px 视口及家居收纳案例。

优化：公共规则只维护一份，技能保留路由、参数、证据和结束条件；日期与单次故障转入回归记录。把“只美国可用 / 接口不可用”等历史观察写成带日期、范围和错误类型的能力记录，并以当轮工具可见性复核。
